# Orcatopia 0.1.0 출시 준비

한국어 · [English](orcatopia-release.md)

아직 공개하지 않은 로컬 후보입니다. 준비 작업은 실행 승인·사용자 섬 변경·태그
게시·공개 디렉터리 등록을 의미하지 않습니다.

## 패키지와 기능

- 표시 이름 Orcatopia, 내부 ID `landmark-island`, 최소 Orca 1.4.248.
- 97개 국가 분류의 랜드마크 100종: 발견 56, 보물 32, 경이 9, 불가사의 3.
  등급 확률은 70/23/6/1%를 유지합니다.
- 장식 208종, 최대 1,044칸 땅, 산책·카메라 추적·캔버스 배치·바닥/기물 분리·두 언어 검색.
- 랜드마크 클릭 시 이동·좌우 방향 메뉴가 열리고 이동 선택 후 목적지를 누르면 완료됩니다.
  저장 형식 v5로 방향을 보존하며 이전 저장은 변환합니다.
- 워크트리 생성으로 얻는 탐험권, 단일·10개 뽑기, 모든 등급의 새 발견 연출과
  건너뛰기 체크박스. 신규·중복 결과를 구분하고 잔여 탐험권에 따라 1개·10개 추가 뽑기를 제공합니다.
  구매·희귀 보장·천장은 없습니다.
- 기기 시각의 낮과 밤, 시간별 타임존 기준 날씨, 로컬 저장·파일 백업/복원.
  한국어·영어는 Orca 언어 설정을 따릅니다.
- Node trusted worker와 `workspace:read`, `storage:own`을 사용하며 권한을 늘리지 않습니다.
- manifest의 아이콘·커버·스크린샷은 기존 자체 그림과 영문 브라우저 DEMO 정원입니다.
  한국어 소개는 한국어 README에 유지합니다. 폰트·사용자 저장·외부 이미지 다운로드는 없습니다.

## 날씨 출시 조건

2026-11-08 사용자가 광고·구독·유료 기능 없는 무료·비상업용 첫 출시를 확정했습니다.
운영 결정은 출시 점검 문서에서 관리하고 제품 소개 문구로 표시하지 않습니다. 이 조건 아래 기존
시간별 Open-Meteo 연동을 유지합니다. 무료 소프트웨어의 모든 배포·사용이 비상업용이라는
뜻은 아니며, 상업 이용은 제공사의 별도 서비스 조건을 충족해야 합니다. 공용 유료 API 키를
다운로드 가능한 번들에 넣지 않습니다. 상업 배포에는 게시 전 별도 인증·운영 설계가 필요합니다.

워커는 기준 좌표와 날씨 조회 항목을 보내며 일반 연결 정보도 제공사에 전달됩니다.
UI와 동봉 고지에 출처 및 네 가지 게임 날씨로 변환했다는 내용을 표시합니다.
캐시·실패 대기는 1시간 동안 유지됩니다. 사용자 전체나 공유 IP에 제공사 한도가 적용될 수
있으며 기기 캐시는 전역 사용량 관리 시스템이 아닙니다. 응답이 없어도 수동·가상 날씨를 쓸 수 있습니다.

근거: [제공사 약관·개인정보 안내](https://open-meteo.com/en/terms),
[동봉 고지](../plugins/landmark-island/licenses/weather.txt).

## 배포 경로

첫 출시는 기존 `tienne/orca-plugins` 사용자 카탈로그, ref `release`,
경로 `plugins/landmark-island` 기준으로 준비합니다. 설치 ID는
`tienne.landmark-island`, 소스 태그는 `landmark-island/v0.1.0`입니다.
기존 Git Logs 파일·릴리스 항목·일반 `vX.Y.Z` 태그를 모두 보존합니다.

공개 검색은 별도입니다. [공개 디렉터리](https://www.onorca.dev/plugins/add)는 공개 저장소
루트의 manifest와 `vX.Y.Z` 태그를 요구합니다. 별도 노출을 원하면 검증한 루트 패키지와
공개 소스·출처를 담은 tienne 소유의 별도 저장소를 사용합니다. ID `landmark-island`는
유지하고 이 저장소의 Git Logs 디렉터리 태그를 재사용하지 않습니다. 저장소·토픽·태그·등록을
생성하지 않았습니다. 실제 게시가 허가되면 정책과 저장소 정체성을 재확인합니다.
같은 ID라도 소스 저장소가 바뀌면 실행 승인이 필요할 수 있습니다.

## 실제 설치와 저장 이전 — 미완료

아래는 실제 출시 전 수동 점검입니다. 사용자 요청에 따라 클릭 검증은 보류합니다.
가능하면 격리 프로필을 쓰고 검증 목적으로 실제 섬을 덮어쓰지 않습니다.

1. `local.landmark-island`에서 백업을 내보내 별도 사본을 보관합니다. 탐험권,
   고유/전체 랜드마크, 재료, 배치, 땅 수를 로컬에 기록합니다. 백업에 워크스페이스
   식별자가 있을 수 있으므로 공개 이슈에 첨부하지 않습니다.
2. 두 정체성이 새 워크트리 이벤트를 각각 받지 않도록 출시 버전 사용 전 개발 버전을 비활성화합니다.
3. 검토한 후보를 최종 정체성으로 설치합니다. 기존 승인은 승계되지 않으므로 별도
   trusted worker 접근을 검토합니다. 새 설치가 기존 워크트리에 탐험권을 지급하면 안 됩니다.
4. 기존 백업 미리보기·확인 절차로 복원하고 기록한 수량과 배치를 대조합니다.
   복원은 합치기가 아니라 전체 교체입니다.
5. Orca를 완전히 종료하고 다시 열어 저장을 확인합니다. 새 테스트 워크트리 하나에
   탐험권 하나, 단일·10개 뽑기, 배치, 백업 저장창, 한국어·영어, 라이트·다크 조작과
   복귀 후 날씨를 확인합니다.
6. 같은 최종 ID의 업데이트 후에도 저장 내용이 유지되는지 확인합니다. 끝날 때까지
   원본 파일과 복원 전 복구 사본을 보관합니다.

워커·브라우저 fixture는 마이그레이션·손상 백업·오래된 복원 미리보기·저장 실패·재시도를
검증하지만 실제 호스트 검증을 대신하지 않습니다.

## CI와 배포 후보

2026-11-08 `release-preview`와 `production`을 생성하고 정확히 `main` 브랜치만
배포하도록 설정했습니다. 운영 환경은 저장소 소유자 `tienne`의 승인이 필요하고,
미리보기에는 배포 승인을 요구하지 않습니다. 소유자가 직접 시작한 운영 배포도
본인이 승인할 수 있습니다. 운영 실행이나 승인은 하지 않았고 기본 GitHub 계정도
전환하지 않았습니다. 승격 작업은 GitHub 호스팅 `macos-15`와 고정 버전 Orca CLI를
사용하므로 자체 러너 등록이 필요하지 않습니다. 활성화 변수는 검토한 워크플로가
`main`에 반영된 뒤 설정합니다.

준비한 자동화는 CI 전에 설정을 검사하고 기본값으로 미리보기를 실행하며,
게시 시 검토한 미리보기의 콘텐츠 해시를 요구합니다. 게시 직전에 환경 규칙도
다시 확인합니다. `pnpm nx run landmark-island:release-preflight --mode=publish`로
GitHub 설정을 바꾸지 않고 점검할 수 있습니다. 환경 설정과 첫 호스팅 미리보기 실행은
[배포 절차](releases.ko.md)를 따라 검토한 `main` 소스로 실행합니다. 소스 통합은
[PR #5](https://github.com/tienne/orca-plugins/pull/5)에서 추적합니다.

2026-11-08 자동화 검증에서는 배포·설정·워크플로 테스트 41개를 모의 검증기로,
같은 41개를 설치된 실제 Orca CLI로 통과했습니다. 고정한 actionlint 1.7.11과
포맷 검사도 통과했습니다. 게시 테스트는 폐기 가능한 로컬 bare 저장소만 사용했고,
실제 읽기 전용 설정 검사는 준비 미완료 상태를 반환했습니다.

호스팅 macOS로 전환한 뒤 모의 어댑터와 새로 다운로드해 체크섬을 검증한
Orca 1.4.252 CLI로 각각 테스트 41개를 다시 통과했습니다. CI에서 사용할 같은
설치 스크립트로 CLI를 임시 폴더에 풀었고, 네트워크를 차단한 상태의 독립 패키지
검증도 통과했습니다. actionlint 1.7.11과 셸 문법 검사도 통과했습니다.
GitHub 원격 실행이 아닌 로컬 검증이며 개발용 Mac에 러너 서비스를 설치하지 않았습니다.

검토하는 정확한 소스 SHA의 [CI](https://github.com/tienne/orca-plugins/actions/workflows/ci.yml)와
[배포 미리보기](https://github.com/tienne/orca-plugins/actions/workflows/release.yml) 결과를
확인합니다. 이전 소스의 성공 결과가 새 후보를 검증하지는 않으며 미리보기는 게시가 아닙니다.

커밋·빌드 후 [기존 후보 준비 명령](releases.ko.md#orcatopia-배포-후보)을 사용합니다.
릴리스 기준을 갱신하고 새 후보의 패키지·카탈로그를 검증하며 기준 대비 Git Logs
하위 트리와 카탈로그 이력이 그대로인지 확인합니다. 보고서의 소스·산출물 커밋과 콘텐츠
해시를 함께 보관합니다. 소스·패키지·기준이 바뀌면 새 후보를 만듭니다.

## 재현 가능한 브라우저 측정

`ORCATOPIA_PROFILE=1 pnpm nx run landmark-island:ui-test --grep='Orcatopia showcase'`로
최대 크기 정원을 캡처하고 `test-results/landmark-island/idle-profile.json`에 기록합니다.
30초 애니메이션 대기 구간 3번과 동작 줄이기 구간 1번을 측정하고 시작·끝 GC 후 힙과
저장 무결성을 확인합니다. 렌더러 메인 스레드 점유율이며 전체 프로세스·GPU CPU나 실제
Orca 메모리가 아닙니다. 2분 fixture 결과로 장시간 누수 부재나 저사양 성능을 보장하지
않으며 실제 호스트·백그라운드·절전 복귀의 장시간 검증은 남겨 둡니다.

## 2026-11-08 로컬 검증

빌드·타입 검사·워커/상태 테스트를 통과했습니다. 앞선 전체 브라우저 점검은 시나리오
82개를 통과했고, 수정한 소개 화면과 선택형 120초 측정도 패키지 UI에서 다시 통과했습니다.
설치된 Orca 1.4.252 CLI와 폐기 가능한 로컬 저장소로 릴리스·워크플로 테스트 22개를
모두 통과했습니다. 사용자 저장소를 푸시하지 않았습니다.

전면에 보이는 정원은 318칸, 배치 랜드마크 5개, 장식 118개였습니다. 애니메이션 25개가
실행 중인 30초 대기 구간 3번에서 렌더러 메인 스레드 점유율은 0.095–0.153%였고,
동작 줄이기에서는 25개 모두 중지됐습니다. GC 후 JS 힙은 시작 6,207,356바이트,
종료 6,207,900바이트였으며 저장 내용은 같았습니다. 실제 Orca·GPU·전체 CPU나
장시간 누수 부재를 뜻하는 결과는 아니고, +544바이트 차이 역시 진단용 관측입니다.

`pnpm validate`에서 두 플러그인의 패키지를 통과했습니다. 해당 점검 당시 Orcatopia는 15개 파일·3,830,546바이트이며 폰트 파일이 없습니다. `plugin inspect`는 기존 두 권한과 trusted worker를 표시하고 실행 승인은 하지 않았습니다. `plugin check`는 통과했으나 HTML 패널의 렌더링 시나리오는 없으므로 실제 조작 검증 증거가 아닙니다.

## 2026-11-09 출시 점검 (한국 시각)

현재 로컬 출시 범위는 랜드마크 100종, 장식 208종, 최대 1,044칸, 랜드마크
이동·방향 메뉴와 저장, 보물 개수 선택 메뉴, 신규·중복 결과 구분과 추가 뽑기입니다.
기존 소개 이미지는 현재 최대 섬이 아닌 이전 샘플 정원을 보여주므로 manifest
설명도 샘플 진행 상태로 명확히 했습니다.

기존 `tienne` 인증으로 읽기 전용 게시 사전 검사를 통과했습니다. 기본 GitHub
계정은 바꾸지 않았습니다. `ORCA_RELEASE_ENABLED=true`, 정확한 `main` 환경 규칙과
운영 승인자를 확인했습니다. 활성 계정 `wad-kwonyunhak`의 변수 조회는 HTTP 403이었으며,
이는 조회 권한 제한이지 배포가 꺼져 있다는 증거가 아니었습니다.

원격 `main`은 `2808d878e46d5a73e3071e64cc68aade443973cc`였습니다. 최근 성공한
게시는 Orcatopia가 아닌 Git Logs 0.2.0입니다. 원격 카탈로그에는 Git Logs만 있고
`landmark-island/v0.1.0` 태그도 없었습니다. Orcatopia 후보는 이 최신 배포 기준을
보존해야 합니다. 로컬 후보 게시 전 소스 통합 후 정확한 main 커밋에서 호스팅 CI와
미리보기가 필요합니다. 실제 설치·재시작·업데이트 검증은 위에 적은 대로 남아 있습니다.

현재 [디렉터리 등록 안내](https://www.onorca.dev/plugins/add)와
[등록 정책](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-listing-policy.md)을
다시 확인했습니다. 사용자 카탈로그 배포만으로 공개 검색 등록이 완료되지는 않습니다.
이번 점검에서 푸시·main 병합·운영 배포·플러그인 실행 승인을 하지 않았습니다.

현재 소스로 빌드·타입·워커/상태 검사, 브라우저 시나리오 93개와 모의 어댑터 기반
배포·설정·워크플로 테스트 41개를 모두 통과했습니다. 설치된 Orca 검증기도 빌드한
패키지를 통과시켰습니다. 호스팅 미리보기나 보류된 실제 설치 검증을 의미하지는 않습니다.
